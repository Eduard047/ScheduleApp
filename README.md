# ScheduleApp

## Огляд

ScheduleApp — система формування, перевірки та публікації університетського розкладу. Клієнт побудований на Blazor WebAssembly (`Client`), серверне API — на ASP.NET Core (`Server`), спільні DTO містяться у проєкті `Shared`. Цільова платформа — .NET 8. Для зберігання даних використовується MySQL 8.0.13 або новіший із провайдером Pomelo.EntityFrameworkCore.MySql. У середовищі розробки доступний Swagger для дослідження API.

## Структура рішення

- `BlazorWasmDotNet8AspNetCoreHosted.Client` — вебклієнт Blazor WASM, Razor-компоненти та клієнтські сервіси.
- `BlazorWasmDotNet8AspNetCoreHosted.Server` — ASP.NET Core хост, контролери, DI-налаштування, контекст EF Core та міграції.
- `BlazorWasmDotNet8AspNetCoreHosted.Shared` — спільні DTO й контракти, що використовуються клієнтом і сервером.
- `database-setup.md` для детального налаштування бази даних.

## Безпека виробничого розгортання

Серверний API навмисно не має автентифікації та рольової авторизації: поточна модель передбачає одного довіреного оператора в локальному або ізольованому середовищі. Не публікуйте застосунок у відкриту мережу: обмежте доступ приватною мережею, VPN або захищеним reverse proxy. Якщо модель розгортання зміниться й доступ отримають взаємно недовірені користувачі, вимоги до ідентифікації та розмежування повноважень потрібно погодити окремо до такого розгортання.

Для оркестратора доступні перевірки `GET /health/live` та `GET /health/ready`. Readiness повертає `503`, якщо база недоступна, початковий сидинг не завершився, залишилися незастосовані міграції або відсутні обов'язкові індекси цілісності.

Якщо TLS завершується на reverse proxy, передайте його точну IP-адресу через `ReverseProxy__KnownProxies__0` (наступні адреси — з індексами `__1`, `__2` тощо). Сервер приймає `X-Forwarded-For`/`X-Forwarded-Proto` лише від цих довірених адрес; не вмикайте глобальну довіру до forwarded-заголовків.

За замовчуванням `AllowedHosts` дозволяє лише `localhost`, `127.0.0.1` та `[::1]`. Для розгорнутого екземпляра задайте точні DNS-імена через змінну середовища, наприклад `AllowedHosts=schedule.example.edu;admin.schedule.example.edu`. Порожнє значення, `*`, `+` та шаблони з `*` навмисно зупиняють запуск. Це налаштування перевіряє HTTP-заголовок `Host`; адресу прослуховування Kestrel задавайте окремо через `ASPNETCORE_URLS`.

## Попередні вимоги

- Встановлений .NET SDK 8.0.100 або новіший (`dotnet --list-sdks`).
- Локальні .NET-інструменти репозиторію: після клонування виконайте `dotnet tool restore`.
- Доступ до локального екземпляра MySQL 8.0.13 або новішого (або сумісного керованого сервісу). Цей мінімум потрібен для функціональних унікальних індексів конфігурації.
- Node.js/npm знадобиться лише за умови зміни фронтенд-інструментів; для запуску поточного рішення не є обов’язковим.

## Швидкий старт

1. Клонуйте репозиторій.
2. Перевірте, що рішення коректно збирається:
   ```
   dotnet build BlazorWasmDotNet8AspNetCoreHosted.Server.sln
   ```
3. Налаштуйте рядок підключення до бази даних (розділ нижче).
4. Застосуйте міграції:
   ```
   dotnet tool restore
   dotnet ef database update --project BlazorWasmDotNet8AspNetCoreHosted.Server
   ```
5. Запустіть серверну частину:
   ```
   dotnet run --project BlazorWasmDotNet8AspNetCoreHosted.Server
   ```

## База даних та EF Core

Реальні облікові дані не зберігаються в репозиторії. Створення локальної MySQL-схеми, Secret Manager, конфігурація `ConnectionStrings:Default`, EF-міграції та production-застереження зосереджені в [database-setup.md](database-setup.md).

## Запуск окремих проєктів

- **Сервер:** `dotnet run --project BlazorWasmDotNet8AspNetCoreHosted.Server`
- **Клієнт:** хоститься сервером, тому додатковий запуск не потрібен.
- **Публікація:** `dotnet publish BlazorWasmDotNet8AspNetCoreHosted.Server -c Release`

## Усунення несправностей

- **`Unable to connect to any of the specified MySQL hosts`** — перевірте, чи запущено MySQL та чи правильні хост і порт у рядку підключення.
- **`Рядок підключення 'ConnectionStrings:Default' не налаштовано`** — додайте рядок через Secret Manager, змінні середовища або локальний конфіг перед запуском EF чи сервера.
- **CORS або 404 для API** — впевніться, що сервер активний, а клієнт звертається до актуального базового URL.

## Автогенерація

Автогенерація працює через чернетки викладачів і безпечний цикл **Сформувати план → переглянути → Прийняти план**. Перед новим семестром задайте початок навчального періоду для кожного курсу; після змін схеми застосуйте міграції та перевірте `/health/ready`.

Стан завдання, скасування, читання плану, пошук останнього доступного відкоту, застосування та відкіт доступні лише тому самому мережевому клієнту, який запустив автогенерацію. Межа визначається неперсональним hash ефективної IP-адреси з урахуванням налаштованих довірених reverse proxy. Після зміни IP попереднє завдання може стати недоступним; клієнти за спільним NAT або proxy належать до однієї межі. Це ізоляція робочого процесу та квот, а не автентифікація користувача.
